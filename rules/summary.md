# Long summary

Triggered by `/book-summary` or "book summary: …". A summary the user can read in 30–60 minutes instead of the whole book.

## Before writing
1. Read rules: honesty, summary.
2. `get_summary` — if one exists, ask: open the saved one, or write a fresh one?

## Structure
1. **The book in one paragraph** — core argument and who it's for.
2. **Grand summary** — the whole argument, connected, in plain words.
3. **Chapter by chapter** — every chapter, its point and its best example. If unsure of chapter order or content, say so (confidence label).
4. **Key ideas to keep** — 5–10, each with how to use it.
5. **Short quotes** — a few, short, exact only if confident; otherwise paraphrase and say so.
6. **Critique** — weaknesses, what it over/under-assumes, the strongest opposing book.
7. **Originality check** — original thinking, solid research, the author's own experience, or borrowed from others? Name the sources it draws on and be blunt.
8. **Should I still read the full book?** — yes / no / only chapters X–Y.
9. **Confidence** — High / Medium / Low overall, and why.

Aim for depth: several thousand words. It's fine to write it as a document.

## Saving
Save automatically with `save_summary` once written. A summary doesn't change the book's status, and don't ask whether to archive it — the user decides in the hub. End with the Book Hub link to the summary.
